## 0. 本文档的定位与用法

1. **本文档只做三件事**：① 把 t1 登记的缺口与风险改写成**可判定**的验证目标（V-*，共 28 条）；② 建立**风险登记册**（R-*，共 30 条，含产品缺陷、工程流程、**夹具/数据形态**三类）；③ 对每个目标给出**可行性裁定**（F-*，共 17 条）与前置条件。
2. **不重复 t1 的事实盘点**：所有"结论+证据+置信度"的原始条目在 [01-基线事实清单.md](01-基线事实清单.md)，本文只引用其编号（G-*、X-*、§x.y）并**新增**本轮独立取得的证据。

4. **口径纪律**：与 t1 一致——「实测」= 本轮亲自跑到原始输出；「源码级」= 只读代码；「未实测」= 明确标注。**数字必须带量纲**（§1.3）。

## 1. 判定规则：什么叫"可判定"（本文档的硬约束）

一个验证目标只有在**同时满足**下列 5 条时才算"可判定"；不满足的，本文档显式标注"条件不足/不可判定"，不粉饰为通过。

| # | 规则 | 反例（本仓库真实教训） |
| --- | --- | --- |
| **K-1** | 必须给出**期望值或守恒等式**，且能算成布尔值（`==` / `≠` / `≥` / `A量 == B量`） | 「质检应能落地」不是判据；「同一 `record_id` 的 `NonconformityRecord` 行数 `+1`」才是 |
| **K-2** | 断言必须落在**业务量**（件数/金额/台账行/DB 状态），**不得只落 HTTP 状态码** | 规划 N-10：历史 11 件超发在 `smoke_test` **全绿**下发生（smoke 只覆盖 GET 状态码与重定向） |
| **K-3** | 必须有**阴性对照**：① 故意改坏断言必须变红；② 非目标场景必须不变（防"过度接线"） | 规划 T-G（exit code 可信度）、T-B（假开关双向差分 + 非返工场景两次相同） |
| **K-4** | 必须有**可复跑性**：写全命令、写全解释器**绝对路径**、写期望输出与 **exit code** | 裸 `python` 在本会话解析到无 Flask 的 conda 缓存解释器（§6 C-1） |
| **K-5** | 必须有**证据坐标**（`file:line`）与**证据类型**（实测/源码级/未实测） | t1 的 18 条文档不一致正是"旧结论无坐标"的后果 |
| **K-6**（v1.1 新增） | **判据的"可分辨性"必须先证明**：若真实库形态让两种假设产生同一观测值，则该判据**不可判定**，必须登记为前置缺陷 | `raw_material` 仅 1 行 `quantity=1.0`：扣料后 `1→0` 同时符合"硬编码 1"与"按实际消耗 1" ⇒ V-07 在真实库形态下不可判定（§4.3 R-28） |

**三条禁令**（源自规划文档，本文档照抄并升级为判定纪律）：

- **禁-1**：**"已接线"不算通过**。"读配置决定 X"必须用 **false/true 双向行为差分**证明（规划 §2 明令）。仅存在调用点/读取点是**必要不充分**条件。
- **禁-2**：**"脚本没报错"不算通过**。`permission_matrix.py` 的 `run()` 在 [第 132 行](../../scripts/permission_matrix.py#L132) **无条件 `return 0`**——它的 exit code **不携带任何断言结果**（本轮源码级复核，§6 C-5）。
- **禁-3**：**"文档这么写"不算证据**。t1 §8 已登记 18 条不一致；本文档追加 C-1/C-3/C-5（§6）。

## 3. 目标明细（分组：判据 / 阴例 / 跑法 / 可行性）

### 3.1 A 组：质检结论落地与门禁（V-01 ～ V-04，全部 P0）
