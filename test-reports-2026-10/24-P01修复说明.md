## 6. 新门禁 `scripts/check_model_refs.py`（TL-01 / G-08）

### 6.1 判据

只认 `<Name>.query` 形态、且 `<Name>` **首字母大写**；对每个函数把下列来源合并为「本函数可解析名字集」：
① 内置名；② **模块级**绑定（import / 赋值 / def / class / 模块级 `try` 内 import）；③ 函数形参（含 `*args`/`**kwargs`/kwonly）；④ **函数体内**绑定（import、赋值含 `for`/`with as`/推导式/walrus、`except ... as`、嵌套 `def`/`class` 名、嵌套形参）。
不在集合内 ⇒ 违规。`M.Consumable.query`（属性链）不在判据内。

**为什么限定「本模块」而不是全仓**：跨模块的仓内类名不算可解析——否则删掉某模块的 import 也不会报红，闸门对 P-01 就完全失效（P-01 的根因正是「本模块没有这个绑定」）。算法与 `harness/improve_plan.py:237` 的候选实现同源（该实现在全 `app/**` 实测「命中 2 / 误报 0」）。

退出码：无违规 `0` / 有违规 `1` / 环境错误 `2`；`--root`（默认 `app`）、`--verbose`、`--json`（机读行）、`--selftest`（13 组内存用例，**零落盘**）。控制台行**全 ASCII**（A-14/A-60），中文只在 docstring。

**边界（有意为之，宁缺勿滥）**：不做数据流/闭包分析（同名被绑定过就放行，故嵌套 `def`/`class` 名、`except as` 别名都算已绑定）；类体级（非函数内）的 `<Name>.query` 不查；无法 `ast.parse` 的文件**计为违规**（不静默跳过）；备份文件名/后缀与 `__pycache__` 跳过（与 `check_properties.py` 同口径）。

### 6.2 与既有门禁的关系

`check_properties.py` 只认「`类名.属性名`」的**属性**存在性（`@property` / 不存在的列），**看不见「名字本身不存在」**这类问题——P-01 的两个端点用 `Consumable.query`，属性与列都没问题，坏的是**名字没有绑定**。新门禁专治这一类（`07` §2.4 / `08` §5.2 G-08）。
