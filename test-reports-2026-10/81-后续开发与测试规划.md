### 1.3 排序模型（业务破坏力 × 依赖 × 成本）

| 因子 | 取值 |

| **I 业务破坏力** | 3 = 资金/台账/库存数字错或安全面；2 = 业务链走不通/半成品；1 = 体验/口径/文档 |

| **C 成本** | 3 = L（5–8 人日）；2 = M（2–3）；1 = S（0.5–1） |

   - **不受约束**（= 本例外）：**经显式授权的数据整治项**（本规划当前**唯一**此类项 = **`B13-02`**：清理 `audit_log` 中 10 行 `target_id NULL` 且 `can_rollback=1` 的存量污染，`id = [7,8,12,15,24,29,40,44,68,73]`）。该类项**必须**写在真实 `app.db` 上才可能达成效用，因此**与「真库零改动」是不同量纲**（不是同一条约束的例外豁免，而是**另一类工作**）。
2. **整治项的四个强制前置（缺一不可）**：
   - **① 先备份 `app.db`**：备份文件 + 备份时的 SHA256/大小/mtime **留档**；
   - **② 可回滚脚本**：正向脚本 + 逆向脚本；脚本内自带「目标行 id 清单」与**前后计数断言**（`count(target_id IS NULL AND can_rollback=1)`：整治前 = **10**，整治后 = **0**）；
   - **③ 执行后复核 SHA256 并登记新锚点**：记录**新** SHA256 + 大小 + mtime + **SQL 全文** + 执行人 + 时点；**原锚点（2531328 / `F5DA2306BC31CBAB098AAD3774016D320A9B9AA3546F93418196AE9900E0F065` / `2026-09-18 12:50:55`）不得被覆盖**，须降级登记为「**整治前**锚点」（append-only 留痕）；
   - **④ 不得在门禁链内执行**：不得写入任何 blocking 步骤、不得由 `ci_gates.py` 编排、**不得进 CI**；整治窗口独立于批次门禁，且**执行前必须先确认 `B17-02`（`DATABASE_URL` 前置闸门 / `C-07`）处于生效态**，以免误写其他库。
3. **整治项的登记与批次收口**：
   - 整治项**单列登记**（编号 + 目标行 id 清单 + 四个前置 + 执行记录），**不写入任何批次 DoD 的「本批验收全绿」**；
   - 因此 **`B13-02` 不构成批次13 的收口判据**（详见 §2 批次13 订正声明）；
   - DoD-3 的「三值逐位相同」与 **DoD-4 的「所有 DB 写入只发生在副本」** 对**未授权项**仍然**全量适用**：**本例外不缩小其适用面**。
4. **本例外不含任何「先改库、后补授权」的空间**：授权**必须在执行前**取得并留档（授权人 + 时点 + 范围）；未取得授权时，`B13-02` 的默认路径（「置 `can_rollback=False`」）**同样不得执行**，**只能登记**。
