## 3. 分两阶段接入（关键设计）

### 3.0 ⚠ 前置硬限定（A-62，来自 t3/E-02 的实测结论）——**先读这一条**
E-02 修好后，本沙箱下 `run_gates.py` 的**自然退出码 = 1**：原生 `route_inventory` **成功**（exit 0）而 `GATES` 把它锁为 `expect_exit=1`（受限沙箱假设）⇒ 这是 **A-42 的自然复现**，也是 D-6 的本意（环境事实变了就不许绿灯）。

**裁决**：
- ❌ **不得**为了 CI 变绿而把 `expect_exit` 重基线化为 0（会把探针变成**恒真断言**，正是 D-6 的反面）；
- ✅ **CI 分组如下（据此实现，勿自行合并）**：

| 分组 | 成员 |
| --- | --- |
| **blocking 集** | `check_templates` / `check_migration_heads` / `check_properties` / `check_db_bootstrap` + `functional_test` + `run_gates.py` 的**非环境依赖部分** |
| **report-only 集** | `route_inventory_native_probe`（环境依赖探针）、`smoke_test`、`permission_matrix`、报告型脚本的退出码（`route_inventory` / `measure_coverage`） |

- 若实现「按沙箱形态探测重基线化」，**必须同时打印 `native_exit` 与 `expected` 两个值**，让「环境变了」可见。
- **复用而非另起**：t3 已把出口语义机读化为 `out['exit_code_semantics']{code,reasons,rule,inputs}`（`run_gates.py:453-461`）⇒ **你的 CI 判据应直接复用它**。

### 3.1 两阶段 rollout

| 阶段 | Jenkins | GitHub workflow | 说明 |
| --- | --- | --- | --- |
| **第一阶段 report-only** | 新增 stage 跑上述 1–9，**失败不阻塞构建**（`UNSTABLE`） | 新增 test job，**不设为 `needs` 前置** | 先观测稳定性与耗时，**避免一上来把管线卡死**；**`route_inventory_native_probe` 的红在此阶段是预期的**（见 §3.0） |
| **第二阶段 blocking** | **按 §3.0 的 blocking 集**设为阻塞 | test job 设为 build 的 `needs` 前置 | 稳定后再收严；**环境依赖探针永远留在 report-only** |

> 依据：`07` E-04 原文「第一阶段 report-only（允许 UNSTABLE），第二阶段起 blocking」。
> **理由**：`smoke_test` / `permission_matrix` 在受限环境会因写盘被拒而假红（A-11），`route_inventory_native_probe` 会因沙箱形态持续红（A-62）——若直接 blocking 会立刻造成「狼来了」。

## 5. 硬约束
1. **不改生产代码**（`app/`、模板、`config.py`）；本任务只动 `Jenkinsfile`、`.github/workflows/*` 与 `harness/` 辅助脚本；
2. **`scripts/` 下既有脚本由 t4 负责**——你若需要 `--no-dump` / `--out` 等参数，**必须等 t4 交付后使用**，不得自行改 `scripts/`；
3. **统一 shim 前缀**（A-8/R-4）：凡走 `_test_bootstrap.make_app()` 的脚本**原生必失败**（`mkdtemp` 0o700 不可写），CI 中必须加 `scripts/_sandbox_compat.py`；
4. **禁止在 CI 里跑会写仓库根 JSON 的形态**（A-11）；
5. **绝对路径解释器**（A-7）：`F:\Miniconda\envs\wage\python.exe` —— PATH 上的 `python` 无 Flask；
6. **编码**（A-14/A-60）：任何新写的 CI 辅助脚本，**主脚本自身**也要 `sys.stdout.reconfigure(encoding='utf-8', errors='replace')`，否则中文/`⇒` 会把「通过」伪装成「崩溃」；
7. 真实库 `app.db` SHA256 全程不变；证据走 E-01 守卫。
