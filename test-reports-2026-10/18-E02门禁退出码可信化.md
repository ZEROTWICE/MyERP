## 5. 编码踩坑记录（A-14）：`⇒` 让「修复生效」伪装成「崩溃」

| 项 | 内容 |
| --- | --- |
| 现象 | 本机 `sys.stdout.encoding = gbk`（`chcp 936`）。当时中间态的 stdout 显式行（`:475`，最终版为 `:485-486`）含 `⇒`（U+21D2）⇒ 直接跑时 `print` 抛 `UnicodeEncodeError`，**进程退出码同样是 1**，与「判据生效的 exit 1」无法区分（captain 实测留档 `evidence/harness/captain-d6fix-verify.txt`） |
| 修法 | ① `main()` 开头 `sys.stdout/stderr.reconfigure(errors='replace')`（保留 GBK encoding，只让不可编码字符降级为 `?`，控制台中文仍可读）；② **所有 print 行 ASCII 化**（`⇒`→`=>`）；③ 只进 JSON / 文档注释的 `⟺ ∧ ∨ ⇒` 保留（UTF-8 写盘无风险） |
| 实测 | 控制台 GBK 直跑（`run_id=w0-e02-t3b-direct2`，`Start-Process` 捕获 GBK 原始字节）：真实退出码 **1**、`probe_unexpected = 1`、`exit = 1  原因=['probe_unexpected=1']`、`Traceback/UnicodeEncodeError 计数 = 0` |
| 附带的取证教训 | ① 读退出码**不能走管道**（管道会覆盖 `$LASTEXITCODE`）；② 子进程输出捕获必须显式编码（`_env.run_child` 已强制 `PYTHONIOENCODING=utf-8`）；③ 用 PowerShell `>` 重定向会写成 **UTF-16LE**（本轮附件生成时踩到，改为按 BOM 识别编码后 `U+FFFD=0`） |
