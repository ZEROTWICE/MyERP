## 2. 三接入位的实装与判据口径

### 2.1 TL-01 `check_model_refs` — **blocking**

```
argv    : <PY> -B scripts/check_model_refs.py
expects : ['violations 0', 'RESULT: OK']
exit    : 0
反向判据: known_bad_absent = P-01 的两个端点 (routes.py / delete_consumable, use_consumable)
```
- **只钉 `violations 0` + `RESULT: OK`**；**严禁钉 `name_query_refs` 计数**（实测 **574 / 575 / 602** 已三次漂移，它随测试资产自增，非判据）。
- 反向判据的口径：在违规段（`found N violation(s):` 之后）匹配 `<basename>:<line>` 与函数名，**避免命中汇总行 / `source` 行的假阳性**。
- 实跑：`checks 5/5`（expects×2 + known_bad_absent×2 + exit×1）。

### 2.2 TL-02 `check_http_contract` — **blocking**（落点 = harness，不迁移）

```
argv    : <PY> -B test-reports-2026-10/harness/w4_http_contract.py \
             --roots app --scope app --expect 10 --json <run_dir>/http_contract.json
expects : ['[w4_http_contract] 会吞成静默出口的站点 = 10', '"sites": 10', '"expected": 10']
exit    : 0
```
- **落点登记为「已由 `harness/w4_http_contract.py` 承担」**（A-85：不迁移到 `scripts/`；槽位原 argv 指向的 `scripts/check_http_contract.py` **不存在**）。
- **基线口径 B**：10 个 P-12 残留站点**具名登记**于 `app/main/routes.py` 的 `:1720 / :5367 / :5420 / :6233 / :7026 / :8067 / :10080 / :10834 / :10976 / :11138`（全为 `get_json()` 维；`get_or_404` / `first_or_404` = 0）。
  - 为何不用 `--scope doc`：`DOC_SCOPE` 只含 **17 个 P-09 函数**，**看不见 P-12** ⇒ 拦不住复发面。
- **`--selftest` 统计行不进 `expects`**。

### 2.3 TL-04 `evidence_hash` — **report-only + 白名单**

```
argv    : <PY> -B test-reports-2026-10/harness/evidence_hash.py --no-strict-coverage \
             --out <run_dir>/evidence_hash.gate.json
expect_exit: None（工具本身在「有白名单内既有违规」时**必须** exit 1，故退出码不作判据）
判据    : ① 无未登记违规  ② 白名单零陈旧  ③ real_db_matches_pinned == true
```
**两个刻意的参数决定（都写了理由）**：
1. **不带 `--strict-index`**：`index_missing` 恒 > 0（本轮新 run 目录未 `--freeze` 的正常形态）⇒ 会恒 exit 1。
2. **带 `--no-strict-coverage`**：只追加模式下「未登记的新增」**本就是允许项**（`added`），而 `coverage_gap` 只在该目录已有索引快照时才触发 —— 实测它被打成的正是队友沿途新建的**根目录文件**（`r2t4-cr-accept-criteria{,.verify}.out.txt`）。**真正要守的「既有文件被改写/删除」两类不受该开关影响**，故这是「allowlist 语义 + 去噪声」，不是放水。

**白名单对拍（实测，零偏差）**：

| 指标 | 值 |
| --- | --- |
| 登记数 `registered_count` | **33** |
| 分型 | `deleted` **20** / `modified` **9** / `phantom_entry` **4** |
| 实测违规数 | **33** |
| **未登记（新出现）** | **0** |
| **陈旧（白名单里已不存在）** | **0** |
| 来源 | captain 侧既有违规（**A-52** 删除类 5 文件名 × 4 份镜像；**A-55** 及同类原地改写 9 条，含 3 份 `_phaseB-prefreeze/<ts>/` 镜像 + `LATEST.txt`） |

## 3. 顺手修复：`--selftest` 统计行恒报 2/5（t5 发现）

**原缺陷**：`w4_http_contract.py` 的统计行另起一个 `len(SiteVisitor(...).sites)` 表达式且**漏调 `visit()`** ⇒ `sites` 恒空 ⇒ 恒 0 ⇒ 只有 `expect==0` 的两个 case 被计入 ⇒ **恒报 2/5**，与判据是否敏感无关。

**修法**：统计行**直接复用循环内的计数变量**（消除重复计算路径）。

| | 修前 | 修后 |
| --- | --- | --- |
| 5 行结果 | 全 `[PASS]` | 全 `[PASS]` |
| 统计行 | `自检 2/5 通过` ❌ 自相矛盾 | `自检 5/5 通过` ✅ |
| 退出码 | 0（由循环内 `ok_all` 决定，**本就可信**） | 0 |

**边界（不夸大）**：原缺陷是**恒假统计行**，不是恒真闸门 ⇒ **不造成假绿**；修它消除了「5 行 PASS 却报 2/5」的自相矛盾，并使该行**可以**被后续步骤安全引用。

## 4. 判据形态 ⑦：注入破坏 ⇒ 入口非零且指名

**方法**：把三个门禁的**输入路径**分别指向 `.tmp/r2t8/` 的合成树（**不触碰仓库与 `evidence/**`**），跑 `ci_gates --only <step>`，断言 **(退出码, 失败指名的步骤 id)** 两点。

| 用例 | 步骤 | 注入方式 | exit | 期望 | `blocking_failed` / `report_only_failed` | 判定 |
| --- | --- | --- | --- | --- | --- | --- |
| **⑦-1** | `check_model_refs` | `--check-model-refs-root` → 合成树含 1 处 `NotABoundModel.query` | **1** | 1 | `blocking_failed=['check_model_refs']` | ✅ PASS |
| **⑦-2** | `check_http_contract` | `--check-http-contract-roots` → 合成树含 **11** 个 P-12 站点（≠ `--expect 10`） | **1** | 1 | `blocking_failed=['check_http_contract']` | ✅ PASS |
| **⑦-3** | `evidence_hash` | `--inject-evidence-root` → 合成证据树**改写** `sample/a.txt` | **2** | 2 | `report_only_failed=['evidence_hash']` | ✅ PASS |

- ⑦-2 用 **11 ≠ 10** 是刻意的：它证明门禁**真的在比数**（而不只是看退出码）——`checks 1/4`，失败项为 `exit == 0`。
- ⑦-3 的关键在于：`modified` 违规**不被白名单覆盖** ⇒ 命中「未登记违规」判据 ⇒ `checks 1/3`。**报告 only ⇒ 整体 exit 2**（不是 1），正是 A-63 第一阶段记 `UNSTABLE` 所需的形态。
- 三个注入开关**只改输入路径、不改任何判据**；`--list` 会把注入后的完整 argv 展开打印，便于复现与审计。
