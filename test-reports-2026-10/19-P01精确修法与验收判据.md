## 1. 缺陷定位（已实证）

| 项 | 值 |
| --- | --- |
| 失败端点 | `POST /consumables/<int:id>/use`（`app/main/routes.py:10936`，函数 `use_consumable`，定义在 `:10939`） |
| 失败端点 | `DELETE /consumables/<int:id>`（同一文件，函数 `delete_consumable`） |
| 根因 | 两函数体引用全局名 `Consumable`，但**模块级导入（`routes.py:6`）不含它**，两函数也**未做函数内导入** |
| 实测形态 | 真实库 `consumables` 表 **0 行**（零行表），故线上表现受行数影响；一旦表内有行（或行不存在、但 `Consumable` 可解析）行为不同 |
| 实证结论 | 模块命名空间**无** `Consumable` ⇒ 两端点 `NameError`；注入该名 ⇒ `POST` 返 **200 且数量 10.0→9.0 真的变化**、`DELETE` 返 **200** |

## 2. 精确改动（单行）

**文件**：`app/main/routes.py`
**位置**：模块级导入行（第 6 行，`from app.models import ...`）
**做法**：在该行**末尾追加** `, Consumable, ConsumableCategory`

- `Consumable`：修本缺陷（两端点恢复）。
- `ConsumableCategory`：**同批预防性补齐**——AST 扫描确认模块级同样没有它，目前只是靠「各端点各自函数内导入」侥幸可用（如「删除易耗品品类」端点 `from app.models import ConsumableCategory, Consumable`）。放在模块级可**消除同一类隐患**，且不改任何既有语义（函数内导入仍然有效，属幂等叠加）。

> 说明：`routes.py:6` 的导入行长达 **705 字符**，请勿整行重写；用行尾追加的方式修改，避免破坏既有导入列表。
