## 1. 目录契约

```text
test-reports-2026-10/evidence/
├── harness/
│   ├── <RUN_ID>/                     ← ★ 新写入的唯一合法落点（每次实测一个 RUN_ID）
│   │   ├── <RUN_ID>-ledger.json      ← 机读台账（唯一权威；40 §4.2 字段冻结）
│   │   ├── <RUN_ID>-ledger.md        ← 人读台账（由 JSON 生成）
│   │   ├── evidence_journal.jsonl    ← 落盘审计流水（只追加；含 renamed_by_guard）
│   │   ├── ci_gates_first.json       ← ci_gates --json 产物
│   │   └── <步骤>.<后缀>              ← 各步骤原始输出（.console.txt / .stdout.txt / .json）
│   ├── *.json / */*                  ← 历史平铺层（t2–t5）：**只读**，新写入不得落这一层
│   └── _phaseB-prefreeze/<stamp>/    ← regression_preflight 的归档副本（**不是新证据**，见 40 §8-C-2）
├── uat/                              ← uat_chains.json（40 锚点之一）
├── api/                              ← api_matrix.json / write_suite.json / non_get_inventory.json
├── analysis/                         ← assertion_ledger.json / coverage_verdict.json / source_assertions.json
├── final/                            ← recount-final.json / recount-pre.json
└── improve/                          ← improve_plan.json
```

| 层 | 可写性 | 规则 |
| --- | --- | --- |
| `harness/<RUN_ID>/` | **可写** | 唯一合法落点；经 `_env.save_evidence()`；**只增不改** |
| `harness/`（平铺层） | **只读** | `_env.evidence_dir()` 在任何形态下都**不会**解析到这一层 |
| `_phaseB-prefreeze/` | 由 `regression_preflight` 写 | 归档副本，**不计入**「证据新增」 |
| `uat/ api/ analysis/ final/ improve/` | 由**报告型脚本**原地写 | ⚠ 这些脚本会**原地覆盖** ⇒ 复跑前必须 `regression_preflight.py preflight` |

## 2. 命名契约

| 对象 | 规则 | 例 |
| --- | --- | --- |
| `RUN_ID` | 环境变量 `HARNESS_RUN_ID`；未设则时间戳 `run-YYYYmmdd-HHMMSS` | `r2-exec-b3-blind` |
| run 目录 | `harness/<RUN_ID>/` | `harness/r2-exec-b3-blind/` |
| 台账 | `<RUN_ID>-ledger.json` / `.md` | `r2-exec-b3-blind-ledger.json` |
| 原始输出 | `<步骤>.console.txt`（ci_gates 风格）/ `<脚本>.stdout.txt` | `ci_gates_first.json` |
| 被守卫改名的落盘 | `<name>.<RUN_ID><ext>`，必要时 `.1` `.2` | `t9-regression-ledger.t9-rega-final.json` |
| ⚠ **改名即风险** | 改名后**新名字不再能区分哪份是终稿**（`run_id`/`baseline` 相同）⇒ 必须靠 `evidence_journal.jsonl`，并在台账 `provenance.superseded_by` 写明取代关系 | 见 `40` §8-C-1 的实例 |
