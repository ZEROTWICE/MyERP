## 8. 坑与教训

### 8.1 门禁与重基线

- **推送前必须复跑完整门禁**。`e057e81` 就是反例：门禁随行改动只做了一半、**且没有复跑门禁就推送** ⇒ 5 个 blocking 失败进了 main，直到下一次会话才发现。**脚本自身的 `RESULT: OK` ≠ 门禁判定通过** —— 门禁的 `run_gates` 步骤拿 `EXPECTED` 对拍脚本输出（如 `templates_files 期望 87 实际 86`），脚本 exit 0 而门禁仍可能 FAIL。
- **删/增任何路由，必须全链路重基线**（一次删 `/auth/register` 动了 8 个键）：`rules_total`、`method_level_GET`、`method_level_non_get_total`、`writable_rules_non_get`、`non_get_uncovered_method_level`（派生）、`multi_method_with_get_*`、`templates_files`、`routes_get_no_arg`，外加 `permission_matrix` 的内联 role 白名单（路由消失 ⇒ 台账 stale）。
- **改任何计数/期望值必须全链路同步**，遗漏一处就产生「阳性对照自相矛盾」。涉及点：`scripts/check_doc_claims.py` 的 `PINNED` + `RETIRED` + caliber-table 文档 + `harness/run_gates.py` 的 `EXPECTED` + `harness/coverage_drift.py` 的 `LOCKED` / `ROUTE_RULES` / `MULTI_METHOD_*` / `synthetic_doc()` / **selftest 夹具与用例标签**。
- **`RETIRED` 规则会随重基线反向失效**：`check_doc_claims.py:135` 的 `get160` 把 160 判为作废值，但 160 现在是 `method_level_GET` 的正确值 ⇒ 重基线时**必须同时退役对应的 RETIRED 条目**，否则 caliber 表一写就被判违规。
- **下限型判据的阴性对照**：`LOCKED['method_level_non_get_total'] = ('>=', 157)` 且现场恰为 157 ⇒ 注入 156 即跌破（`CD-N3` 即此）。**下界==现场是最敏感的设定**，不要为了「留余量」把下界调低于现场，那会让门禁失敏。
- **`check_doc_claims` 不带 `--coverage` 必红 11 条**，属结构性缺失，不是回归。
- **`check_properties.py` 不接受 `--phase`**。
- **`coverage_drift.py` 的落盘名是 `route_inventory.stdout.txt`**（不是 `route_inventory.txt`）。
- 管道会吃掉退出码（`cmd | tail` 的 `$?` 是 `tail` 的）⇒ 判退出码必须用 `[e03] exit_code_semantics` 行或 `PIPESTATUS`。

### 8.2 架构陷阱

- **`SQLALCHEMY_ENGINE_OPTIONS` 不可无条件施加 PG 专有参数**：`connect_args={'connect_timeout':10,'application_name':'myerp'}` 只有 psycopg2 认；SQLite 回退路径会抛 `TypeError: 'connect_timeout' is an invalid keyword argument for Connection()`，**每个启动 app 的门禁步当场崩溃**（`config.py` 现按 `uri.startswith('postgresql')` 分支，勿回退）。
- **`Config` 里别用 `_IS_PG` 这类类属性**：`str.isupper()` 为真 ⇒ 会被 Flask `from_object` 抄进 `app.config`。
- **PG 保留字**：`SELECT COUNT(*) FROM user` 返回当前用户而非表；必须 `SELECT COUNT(*) FROM "user"`。
- **`lock` 生成是平台相关件**：`check_lock` 的「声明依赖未进 lock」判据须**先求值环境标记**（已修为 marker-aware），否则 Windows 生成的 lock 与 Linux 生成互判失败。
- **bootstrap 自举链**：`app/__init__.py:243-246` `_ensure_schema()` → `bootstrap_if_empty()` → `_seed_system_configs()`；空库 + 无种子 ⇒ `_init_admin_if_empty()`（`INIT_ADMIN_PASSWORD`）。`.dockerignore` 的 `*.db` 会把任何 DB 挡在构建上下文外。
- **gunicorn 入口 `main:app`**，`main.py:5` 是模块级 `app = create_app()`，`:7` `__main__` 守卫 ⇒ `from main import app` 不起服务器。

### 8.3 载体与工具

- **`MALFORMED_RESPONSE`（tool input invalid JSON）多发于一次性大载荷写入回合**。对策：**禁 `write` 整文件重写**，改小段 `edit`；读数先落 task output（≤2KB）；`read` 带 `offset`/`limit`；子代理 executionPrompt 里写死这些纪律。
- **载体故障不保证零副作用**：失败回合可能已写入部分改动 ⇒ 重派第一步必须现场 `grep`/读盘确认状态，再决定改哪里。
- **`agent_teams_amend_task` 未指定字段会重置为默认值**（曾把 objective 重置、把 inScope 塞进自动生成的路径）⇒ **必须同时传 objective + acceptance + inScope + outOfScope**。
- **结构化 `changedPaths` 校验不展开通配符**：inScope 用通配符时，单模板路径/新 JS 文件会被报 `undeclared`；省略该字段又要求必填 ⇒ **任务 inScope 写精确路径**。
- 本会话 `compress` 工具长期死锁（多次报「already compressed in active block(s) … Refold blocked」且 `decompress` 无 `inline` 参数）⇒ **不要反复重试 compress**，它会在有新范围时才可用。
