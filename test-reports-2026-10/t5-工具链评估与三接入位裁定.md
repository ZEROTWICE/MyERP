**【本任务新发现·自证行恒假】`--selftest` 的统计行恒报 `2/5`**

```
命令：python -B test-reports-2026-10/harness/w4_http_contract.py --selftest
输出：5 行全部 [PASS]（WT-P1/P2 期望 0 实测 0；WT-N1/N2/N3 期望 1 实测 1）
      [w4_http_contract] 自检 2/5 通过        ← 与 5 行 PASS 自相矛盾
exit：0
```
**根因（AST 抽取真表达式后求证）**：统计表达式的源片段是
```
sum(1 for n, s, e in cases if len(SiteVisitor('<s>', s.splitlines()).sites) == e)
```
它**漏调 `visit(ast.parse(s))`** ⇒ `sites` 恒为空 ⇒ `len(...)` 恒 0 ⇒ 只有 `expect==0` 的两个 case 被计入 ⇒ **恒等于 2/5，与判据是否敏感无关**。

**三重取证**：① 求值该生成器表达式 ⇒ `sum = 2/5`（与真实输出一致）；② 同一批 5 case 逐项**调用 `visit()`** 后复算 ⇒ **5/5 全过**；③ `SiteVisitor('<s>', 单个 bad case 源码).sites == []`（len 0），调用 `visit()` 后 `== 1`。

**影响与边界（不夸大）**：
- 它是**恒假统计行**，**不是**恒真闸门 ⇒ **不造成假绿**；
- **退出码仍可信**：`exit` 由循环内 `ok_all` 累积决定，任一 case 由 PASS 变 FAIL ⇒ `exit 1`；
- 但若把该行纳入 CI `expects`，会得到**恒不匹配**的判据；
- 若下游（人/机）误读「2/5」为「判据不敏感」，会错误地**放行**或误判本门禁不合格。
- **修法**：统计表达式补 `.visit(ast.parse(s))`，或**直接复用循环内的计数变量**（推荐后者，消除重复计算）。
